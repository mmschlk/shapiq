# Core Array Abstractions

shapiq uses nominal array-like abstractions for games and player sets instead of Python lists of objects. `Game` and `Players` expose logical `shape`, `ndim`, and `size` while hiding representation axes such as player-set storage, interaction storage, and value dimensions. Scalar objects are zero-dimensional instances of those same abstractions rather than separate public types. Explanation results are games, following [ADR 0004](0004-everything-is-a-game.md).

Coalition representations are selected by `Players[C]` rather than requiring a universal nominal coalition container. A player implementation may accept native boolean JAX arrays whose final axis records player membership, or another representation appropriate to its player sets. That implementation owns compatibility checks and distinguishes coalition batch axes from internal axes. This keeps domain metadata with the player sets while allowing coalitions to use existing array representations. These abstractions describe domain elements rather than numerical scalars and do not require the full numerical Python Array API.

Mathematical capabilities and storage families are independent. Capabilities such as k-additivity are protocols; concrete array-backed game representations compose `Game` with ndlike's `JaxAxisProtected` and specify their protected axes. Dense/sparse layouts belong to those concrete game families, not to a separate explanation-container hierarchy. The abstract base does not impose a memory layout.
