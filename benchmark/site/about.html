About the benchmark

We compare Shapley estimators on games built from real datasets. Each estimator receives a coalition-query allowance and is compared with an exact reference for the same frozen game.

This page describes the approved 24-dataset benchmark now being implemented. The dashboard still displays the earlier published cohort. It will be replaced when the new results and coverage have been checked; intended counts below are not a claim of completed measurements.

Scope

One benchmark covers individual predictions, data valuation and feature selection, with four game-construction seeds and three estimator seeds. The resource ceiling is 1,024 CPUs and 24,576 allocated CPU-hours, including preparation and prior work. Preparation and evaluation run together. A game receives at most two CPU-hours to prepare its exact reference; resource exclusions and failures remain visible.

Include the natural full input width below sixteen, and only feasible dimensions and row counts. Never pad features or manufacture players. Feature subsets and neighbor-row prefixes are nested within a construction seed. Group count and model input width are separate axes in data valuation.

Exhaustive tables contain 16, 256, 4,096, 16,384 or 65,536 coalition values at 4, 8, 12, 14 or 16 players respectively. Existing direct derivative formulas avoid dense exponential-by-exponential matrices above twelve players. Exact means exact for the saved game, subject to documented floating-point error. Native solvers must match the game's utility, masking convention and supported target. We do not claim generic exact truth at hundreds of players.

Models and controlled comparisons

Linear/logistic models and random forests provide a matched core across all 24 datasets and the three applications. Random forest, XGBoost and LightGBM supply native tree games. At twelve players, XGBoost, LightGBM, SVM and MLP comparisons use a fixed balanced subset: Adult, Breast Cancer, Digits, Bioresponse, Wine Quality, Miami Housing, Superconductivity and QSAR-TID11.

The same subset has a separate input-width sweep at twelve valuation groups: 8, 16, 32, 64, 128 and the full width where feasible, using the core models. No dataset or model is selected because its estimator scores look favorable. Train/validation/test splits and model profiles are fixed and recorded.

The generated design contains 1,270 recipes and 5,080 intended instances before resource and model-quality exclusions: 782 exhaustive recipes, 360 native tree recipes and 128 native neighbor recipes. Four construction seeds are crossed with three estimator seeds; design counts are not measured coverage.

Estimators, budgets and scores

Retain the 22-estimator catalog and its explicit constructor settings. Evaluate nine relative query budgets: 0.5, 1, 2, 4, 8, 16, 32, 64 and 128 times the player count. Requested budgets and actual queries are separate; small games can saturate their entire coalition space. Unsupported method/target combinations remain explicitly unsupported.

Use the existing target-aware coefficient-error metrics and weighting rules. The three applications receive equal weight; dense dimension or model grids do not automatically give a dataset more influence. Zero-energy targets have no normalized score. Failures have no invented timing or error value. Report success coverage alongside scores, with construction seeds grouped for uncertainty.

Timing and reproducibility

Games, model settings, selected rows and columns, payoff tables, reference values and random seeds are frozen. Dataset caching prevents repeated downloads, and workers use one CPU each. Cached-game estimator timings are diagnostic; recorded batch-amortized oracle costs are not direct measurements of an uncached run.

The final report will include actual coverage, unsupported combinations, resource exclusions and reproduction artifacts. Historical results stay available until the replacement is ready. No approximate high-dimensional reference is presented as exact ground truth.
