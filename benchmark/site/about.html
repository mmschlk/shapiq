About the benchmark

How well can we estimate contributions with a limited number of queries? Scope version 2 compares 22 estimator configurations across individual predictions, training data and feature selection on all 24 datasets.

Games, Shapley values and estimation error

  • Game: for players \(N = \{1, \ldots, d\}\), a function \(f: 2^N \to \mathbb{R}\) assigns a value \(f(S)\) to each coalition \(S \subseteq N\). The applications below define the players and \(f\).
  • Shapley value: player \(i\)'s average marginal contribution across all player orderings:
\[\phi_i = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!\,(d - |S| - 1)!}{d!}\left[f(S \cup \{i\}) - f(S)\right].\]
  • Estimator: an algorithm queries \(f\) at most \(B\) times and returns an estimated vector \(\hat{\boldsymbol{\phi}}\), to approximate the exact contribution vector \(\boldsymbol{\phi}\).
  • Normalized mean squared error (nMSE):
\[\mathbf{nMSE} = \frac{\lVert \hat{\boldsymbol{\phi}} - \boldsymbol{\phi} \rVert_2^2}{\lVert \boldsymbol{\phi} \rVert_2^2}.\]

Lower is better: zero is exact; one is the error of estimating every contribution as zero. Zero or negligible reference vectors are excluded. For interaction targets, the vectors contain the requested interaction coefficients; the empty-coalition baseline is excluded. Main effects and pairs can also be viewed separately.

The selected cohort has 512 recipes and 2,048 prepared instances, with four construction seeds per recipe: 477 core recipes and 35 KNN/TNN recipes. Every selected instance has a qualified reference. All 20 required estimators have 100% successful supported coverage; ShaplEIG and SPEX retain partial coverage. The tables show selected player grids; estimator coverage counts only eligible, supported cells.

Thirty-five core recipes were excluded in full because at least one seed failed the model-quality check against a dummy predictor. Neighbor replacements were selected for balanced coverage without using estimator accuracy; the selection manifest records the exclusions and deterministic replacement rule. All 24 datasets and all three applications remain represented. Historical broader results outside this selection do not count toward this cohort’s coverage.

Explaining an individual prediction

Players are input features. Fit a predictor \(h\) once and explain one held-out point \(x\). For the small games, keep \(x\)'s selected features and replace the others with fixed training-background means \(b\):

\[f(S) = h(z(S)) - h(b), \qquad z_i(S) = \begin{cases}x_i & i \in S,\\ b_i & i \notin S.\end{cases}\]

The output is a fixed class probability or a regression prediction. Exact reference: evaluate all \(2^d\) coalitions.

Tree games extend this to larger player sets. Interventional games average predictions with missing features filled from fixed background rows. Path-dependent games average missing branches using training-path weights. Matching exact tree solvers supply the references. Both tree constructions use random forests only.

Models: linear/logistic regression and random forest for baseline games, with nested feature sets of at most 12 players. RF tree games use 8, 16 and 32 features where available. A dataset's full width below 12 is also included in the baseline grid. There are no extra-model contrasts. Each table lists the retained model-specific grids; “—” means no selected recipe for that model/construction.

Valuing training data

Players are groups of training rows. For a coalition \(S\), fit \(h_S\) on the union of its groups and evaluate on a fixed held-out set \(T\):

\[f(S) = \begin{cases}\operatorname{accuracy}(h_S, T) & \text{classification},\\ -\operatorname{MSE}(h_S, T) & \text{regression},\end{cases} \qquad f(\varnothing) = 0.\]

Exact reference: refit and score every coalition of 4, 8 or 12 groups. Both linear/logistic regression and random forest use exactly \(\min(12, \text{dataset width})\) input features. There is no input-width sweep; input width is separate from the number of players.

Neighbor games use individual training rows as players for a fixed test example. KNN utility counts matching labels among the coalition's nearest \(\min(k, |S|)\) rows, divided by fixed \(k\). TNN utility is the matching-label fraction within a fixed radius, or \(1 / \text{number of classes}\) when no rows are present. Selected classification games use 32 or 64 players, with exact native Shapley references. All input selections are fixed before estimator evaluation.

Selecting useful features

Players are input features. For every coalition \(S\), fit a fresh predictor \(h_S\) using only those columns, keeping the training and held-out rows fixed:

\[f(S) = \begin{cases}\operatorname{accuracy}(h_S, T_S) & \text{classification},\\ -\operatorname{MSE}(h_S, T_S) & \text{regression},\end{cases} \qquad f(\varnothing) = 0.\]

Exact reference: fit and score all \(2^d\) coalitions. Unlike an individual-prediction game, this measures how well a model can learn from the chosen features.

Models: linear/logistic regression and random forest, with the same nested feature grids of at most 12 players used by the baseline prediction games.

Comparing and reproducing results

  • Budgets: 0.5, 1, 2, 4, 8, 16 and 32 × \(d\) coalition queries; three estimator seeds per game. Actual query use can be smaller.
  • Targets: Shapley values and order-two k-SII, SII, STII, FSII and FBII interactions, where supported. KNN/TNN games provide SV only.
  • Scores: weighted means and medians. Applications receive equal weight, followed by subtype and recipe; datasets with more recipes can have more weight.
  • Completion: 100% successful supported coverage for every estimator except ShaplEIG and SPEX. ProxySPEX is included. Failed and missing runs for the two exempt estimators remain visible and unscored.
  • Coverage: exact-reference coverage and successful estimator coverage are separate. Unsupported targets are not failures. Zero-signal and quality exclusions are reported without changing frozen games to improve coverage.
  • Ground truth: exhaustive tables for generic games of at most 12 players; matching exact native solvers for random-forest tree and neighbor games. References are subject to floating-point precision; small-game solver checks do not establish independent full-dimensional validation.
  • Data notes: Wine classification differs from Wine Quality regression. NHANES I uses its supplied survival label as a regression surrogate.
  • Timing: measured estimator time on cached games; estimated oracle costs are shown separately. These are diagnostic timings, not isolated end-to-end timings.
  • Reproduction: the dashboard exports selected results as JSON or CSV. Historical broad-cohort artifacts remain available separately and do not contribute to this cohort. Frozen-game reproduction preserves authenticated references, original result identities and the source overlays used by each run.

Estimator combinations

For each target and budget, we fit signed linear weights with no intercept:

\[\hat{\boldsymbol{\phi}}_{\alpha} = \sum_{m=1}^{M} \alpha_m \hat{\boldsymbol{\phi}}^{(m)}.\]

Complete panels contain the same game, budget and seed for every supported nonexempt estimator. Dataset-grouped cross-validation keeps all games from a dataset together. Held-out normalized R² and nMSE compare the fitted combination with equal weights. PCA of normalized estimator errors describes shared error patterns. Signed coefficients may be negative and are not importance scores.
